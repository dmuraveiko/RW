Подсистема пополнения RW

Взаимодействует с прочими подсистемами по NATS (без JetStream)
Только асинхронные запросы Publish-Subscribe, не синхронные Request-Reply

Получает информацию о том, какие кошельки-получатели нужно отслеживать
Отдает информацию какие кошельки зарегистрированы для получения какого количества пополнений
Активирует (по запросу) процедуру пополнения нашего кошелька USDT, блокирует кошелек-получатель от других пополнение, если это надо
Отслеживает успешность пополнения
Уведомляет о результате
Идентифицирует баланс пользователя
Отправляет информацию о пополнении в подсистему баланса
Отмечает неидентифицированные платежи (размещается в отдельной таблице БД)

Взаимодействует с заказчиками (инициаторами) пополнений
С сервисом балансов
С сервисом наблюдения за кошельками (с помощью которых определяется статус платежа)

Режимы работы операций пополнения:

1) Пополнение по 4-м "копейкам" и фиксированному кошельку-получателю, неограничено по времени и по количеству операций
2) Пополнение по фиксированному кошельку-получателю и фиксированному кошельку-отправителю, неограничено по времени и количеству операций
3) Пополнение ограниченное по времени, наш фиксированный кошелек-получатель выделяется на ограниченное время для этой операции
   а) Известный кошелек-отправитель
   б) Любой кошелек-отправитель

Каждый раз когда выбирается доступный кошелек - выбирается из списка доступных кошелек с минимальной суммой USDT на этом кошельке

Для "вечных" операций (фиксированные кошельки, 4 "копейки") привязки кошельков/идентификаторов баланса могут быть изменены. 
Поэтому ведем историю привязок

По очевидным причинам кошельки, которые используются:

Для пополнения методом 4 "копейки
Для пополнения методом с фиксированным отправителем
Для пополнения методом, с ограничением по времени

это разные списки кошельков

При регистрации пополнения определяем были ли пополнения уже зарегистрированы для этого идентификатора пользователя этим методом
И отдаем информацию для уже зарегистрированного пополнения

==========================================================================================================================

Пополнение по 4-м "копейкам"

Значение 0000 "копеек" не используется
Недопустимы идентификаторы, где первая и последняя цифра 0 
Идентификаторы выдаются не подряд (не по возрастанию числа)
В адрес одного кошелька-получателя может быть только единственный такой 4-х цифирный идентификатор. Заложить это ограничение и в код нашего сервиса и в constraint БД

Регистрируется вечное ожидание пополнения в пользу некого идентификатора баланса
Для этого находим доступный кошелек-получатель (где еще не все комбинации 4-х значные заданы). Выдается 4-х значный идентификатор

Возможна ситуация смены кошелька-получателя. Кошелек-получатель выдается новый.
Но ранее выданный 4-х значный идентификатор, привязанный к идентификатору баланса, не меняется при этом

При выдаче нового кошелька сохраняется история старых привязок

При любой успешной операции пополнения кошелька-получателя идентифицируем по 4-м копейкам баланс пользователя и пополняем его

Неидентифицированная операция помечается отдельно (размещается в отдельной таблице БД)

==========================================================================================================================

Пополнение по фиксированному кошельку-получателю и фиксированному кошельку-отправителю

Регистрируется вечное ожидание пополнения в пользу некого идентификатора баланса, кошелек-отправитель при указывается при регистрации
Находим доступный кошелек-получатель, запоминаем соостветствие в БД, отдаем кошелек-получатель

Наблюдаем за кошельком-получателем, при поступлении денежных средств от зарегистрированного кошелька-отправителя пополняем баланс в сервисе балансов

Неидентифицированная операция помечается отдельно (размещается в отдельной таблице БД)

==========================================================================================================================

Пополнение, ограниченное по времени

Регистрируется ожидание пополнения в адрес конкретного идентификатора сервиса балансов
Находим доступный кошелек, с минимальной суммой USDT на этом кошельке
Доступный означает, что кошелек не используется для других пополнений и выполнен защитный интервал (когда предыдущее пополнение по времени было завершено не позднее X минут до этого)
Для пополнений с известным кошельком-отправителем можно зарегистрировать несколько таких пополнений на один кошелек-получатель
Для пополнений с неуказанным кошельком-отправителем зарегистрировать можно только одно пополнение одновременно

Ожидаем пополнения USDT на этом кошельке (это может быть как одна так и несколько отдельных операций)
При поступлении USDT идентифицируем платеж и пополняем баланс в сервисе балансов

Неидентифицированная операция помечается отдельно (размещается в отдельной таблице БД)

Защита от "спама":

Нужно установить ограничение регистрации пополнения в адрес одного идентификатора балансов 
Так как количество кошельков-получателей ограничено, то пользователь может постоянными запросам пополнений заморозить нам возможность получать пополнения в адрес других идентификаторов баланса

Одновременно может быть только одно пополнение ограниченное по времени в адрес одного идентификатора балансов

Следующее такое пополнение может быть осуществленно только после какого-то защитного интервала (интервал по умолчанию 30 минут, передается через переменную среды окружения)

При отказе в регистрации пополнения нужно возвращать информацию о том, когда пополнение можно будет зарегистрировать
(чтобы пользователь понимал когда ему повторить операцию)
